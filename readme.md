# uosc_danmaku_module_pakkju

**在 mpv 弹幕插件 [uosc_danmaku](https://github.com/Tony15246/uosc_danmaku) 上做的三个独立增强。**

| # | 功能 | 解决什么 | 面向谁 | 开关 |
|---|---|---|---|---|
| **一** | **pakku 弹幕合并** | 同一句话被几百人重复发、还各带错别字和谐音，自带合并认不出来 | 所有人（桌面 / 安卓都一样） | `pakku_enable` |
| **二** | **无键盘支持** | 安卓 mpv / 遥控器 / 手柄没有键盘，搜索框打不了字、结果列表选不了 | 主要面向安卓 | `danmaku_auto_select` 等 3 项 |
| **三** | **保存过滤后的弹幕** | 上游的「保存弹幕」只能存**原始**弹幕，存不到过滤/合并之后的结果 | 想归档或分享的人 | `save_danmaku_mode` |

三个功能**互不相干**，可以只用其中一个：

- 只在电脑上看番 → 只需要**功能一**（覆盖脚本即可，什么配置都不用改）
- 只在安卓上折腾 → 三个都建议开，但**功能二**才是关键
- 想把「我看到的弹幕」存下来 → 只要**功能三**

> 本文只讲怎么用。合并算法的原理（编辑距离、拼音距离、余弦相似度、
> 滑动窗口聚类）见文末的出处博客。

# 功能一：pakku 弹幕合并

## 它解决什么问题

uosc_danmaku 自带的合并（`merge_tolerance`）只能合并**文本一模一样**的弹幕。
本功能补了三级模糊判定：

| 弹幕原文 | 自带合并 | 加上本功能 |
|---|---|---|
| `完结撒花` `完结撒花` `完结撒花` | ✅ 合成一条 | ✅ 合成一条 |
| `完结撒花` `完结撒花！！！` `完结撒花~` | ❌ 各显示各的 | ✅ 合成一条（文本预处理） |
| `哈哈哈哈` `哈哈哈哈啊` | ❌ | ✅ 合成一条（编辑距离） |
| `在吗` `再吗`、`是` `事` | ❌ | ✅ 合成一条（拼音相同） |
| `好看` `好看啊` | ❌ | ✅ 合成一条（余弦相似度） |

四级判定按顺序执行，**任意一级命中就合并**，然后：

- 末尾标上被合并的次数 —— `完结撒花(12)`
- 合并得越多显示得越大（默认最多放大到 2 倍）
- 标的是**普通半角括号数字，跟随正文字体**，不需要额外装字体

```
完结撒花(12)
👍👍👍👍👍👍👍👍👍👍(69)
kksk(46)
```

## 实测效果

3 集真实弹幕（合计 20086 条），其中一集：

```
合并前    6702 条
合并后    4884 条    减少 27%
耗时      约 320ms    只在弹幕加载时执行一次
最大合并  👍 刷屏，合并了 69 条
```

## 怎么开启

```ini
pakku_enable=yes
```

**本仓库的 `uosc_danmaku.conf` 里已经默认写好 `yes`**，所以覆盖文件后重启 mpv 即可。

> 注意区分两个「默认值」：模块代码里的默认是 `no`（避免升级后行为突变），
> 本仓库的 conf 显式写成 `yes`。详见[默认值对照](#默认值对照代码-vs-本仓库-conf)。

## 怎么确认生效

看日志里 `已解析` 的条数：

```
[uosc_danmaku] 已解析 4884 条弹幕
```

条数明显少于弹幕总数，说明合并生效了。想看详细统计：

```powershell
mpv.exe --msg-level=uosc_danmaku=v "你的视频.mkv"
```

```
[uosc_danmaku] pakku: 拼音字典载入 6763 个汉字 / 398 个拼音组
[uosc_danmaku] pakku: 6702 条 -> 4884 条（簇 4884，最多合并 69；
               ==467 ≤1058 P46 247%；丢弃 0，缩小 0，放大 73，耗时 319ms）
```

统计行怎么读：

| 片段 | 含义 |
|---|---|
| `6702 条 -> 4884 条` | 合并前后条数 |
| `最多合并 69` | 最大的一个簇合并了 69 条 |
| `==467` | 467 条靠「文本完全相同」合并 |
| `≤1058` | 1058 条靠「编辑距离」合并 |
| `P46` | 46 条靠「拼音」合并 |
| `247%` | 247 条靠「余弦相似度」合并 |
| `丢弃 / 缩小 / 放大` | 密度调控与字号放大的命中数 |
| `耗时 319ms` | 整个合并过程花了多久 |

## pakku 选项全表（23 项）

全部写在 `script-opts/uosc_danmaku.conf` 的 pakku 段里。**改完要重启 mpv。**

「默认值」一列是**模块代码里的默认值**（`modules/options.lua`）；
「本仓库」一列是本仓库 conf 里显式写的值。两者不同的地方都标了 ⚠️。

### 开关与判定（最常调的 5 项）

| 选项 | 默认值 | 本仓库 | 说明 |
|---|---|---|---|
| `pakku_enable` | `no` | ⚠️ `yes` | 总开关。**开启后接管 `merge_tolerance`**（后者失效） |
| `pakku_threshold` | `30` | `30` | 滑动窗口秒数，只有同一窗口内的弹幕才互相比较。调大合并更多但更慢 |
| `pakku_max_dist` | `5` | `5` | 字符频率编辑距离上限。越大越容易把不同文本判为相似。`0` = 只靠拼音和余弦 |
| `pakku_max_cosine` | `45` | `45` | bigram 余弦相似度阈值（0-100）。**填 >100 可禁用这一级** |
| `pakku_use_pinyin` | `yes` | `yes` | 拼音距离，用于合并谐音弹幕（`在`/`再`、`是`/`事`） |

### 合并范围与标记

| 选项 | 默认值 | 本仓库 | 说明 |
|---|---|---|---|
| `pakku_cross_mode` | `yes` | `yes` | 是否允许滚动/顶部/底部**不同类型之间**合并 |
| `pakku_mode_elevation` | `yes` | `yes` | 把底部弹幕提升为优先级最高的类型 |
| `pakku_mark` | `suffix` | `suffix` | 数量标记位置：`off` / `suffix`（`恭喜(12)`）/ `prefix`（`(12)恭喜`）。⚠️ pakku.js 默认是 `prefix`，本项目沿用后缀 |
| `pakku_mark_threshold` | `1` | `1` | 合并数量超过该值才加标记。`1` = 只要有合并（≥2 条）就标 |
| `pakku_representative_percent` | `20` | `20` | 取簇内第百分之几的成员作为代表（决定合并后的时间、颜色、字号） |

### 标记的字形与字号

| 选项 | 默认值 | 本仓库 | 说明 |
|---|---|---|---|
| `pakku_mark_subscript` | `no` | `no` | `no` → `(12)` 普通数字跟随正文字体；`yes` → `₍₁₂₎` 下标。⚠️ pakku.js 默认是下标，本项目默认关掉 |
| `pakku_mark_scale` | `1.8` | `1.8` | **仅当 `mark_subscript=yes` 时生效**的额外放大倍数，补偿下标字形天生偏小 |

关于标记，值得多说一句**为什么默认不用下标**：

下标数字的字形高度只有正文字体的约 **55%**（实测在 47%~63% 之间浮动，随字体变化），
看着明显偏小而且换字体就变样。pakku.js 用下标是因为它在网页里；
本项目用普通数字跟随正文字体，观感更稳定，也不占额外的字号预算。

如果你就想要 pakku.js 那种下标观感：

```ini
pakku_mark_subscript=yes
pakku_mark_scale=1.8      # 1.0 = 还原 pakku.js 原始观感（会明显偏小）
                          # 1.46 = 下标括号与正文数字同高
                          # 1.8  = 下标数字与正文数字同高
```

### 字号放大（让热门弹幕更醒目）

| 选项 | 默认值 | 本仓库 | 说明 |
|---|---|---|---|
| `pakku_enlarge` | `yes` | `yes` | 是否按合并数量放大字号 |
| `pakku_enlarge_min_count` | `5` | `5` | 合并数量超过该值才**开始**放大 |
| `pakku_enlarge_max_scale` | `2.0` | `2.0` | 放大上限倍数 |
| `pakku_enlarge_log_base` | `5` | `5` | 放大系数的对数底数。默认 5 时**合并 25 条即到上限 2 倍** |

### 文本预处理

| 选项 | 默认值 | 本仓库 | 说明 |
|---|---|---|---|
| `pakku_normalize_display` | `yes` | `yes` | 合并后显示**预处理过**的文本；`no` 则显示出现次数最多的原始文本 |
| `pakku_trim_ending` | `yes` | `yes` | 去掉尾部标点（`完结撒花！！！` → `完结撒花`） |
| `pakku_trim_width` | `yes` | `yes` | 全角转半角 |
| `pakku_trim_space` | `yes` | `yes` | 合并多余空格 |
| `pakku_forcelist` | 见下 | 同左 | 自定义替换规则，JSON 数组 `[[模式, 替换], ...]` |

`pakku_forcelist` 默认值：

```ini
pakku_forcelist=[["^23{2,}$","23333"],["^6{3,}$","66666"]]
```

含义：`233333…` 全部归成 `23333`，`66666…` 归成 `66666`。

- 模式是 **Lua 模式**（不是正则），但额外支持 JS 风格的 `{n}` / `{n,}` / `{n,m}` 量词
- 想加自己的规则就往数组里追加，例如把「哈哈哈哈」统一：
  `[["^哈{3,}$","哈哈哈"]]`

### 密度调控（进阶，默认全关）

| 选项 | 默认值 | 本仓库 | 说明 |
|---|---|---|---|
| `pakku_shrink_threshold` | `0` | `0` | 同屏密度超过该值后**整体缩小字号**。`0` = 禁用 |
| `pakku_drop_threshold` | `0` | `0` | 同屏密度超过该值后**按权重丢弃**低优先级弹幕。`0` = 禁用 |

> ⚠️ 这两项的数值**跟你的 `fontsize` 强相关**，没有通用值。
> 值越小越容易触发。想开的话从 `fontsize` 的 1~2 倍开始试。

# 功能二：无键盘支持（安卓、遥控器、手柄）

## 为什么需要

uosc_danmaku 原本的弹幕搜索流程是「**输入关键词 → 从列表里选番剧 → 从列表里选集**」，
而安卓 mpv（如 mpvex）上这两步都做不了：

| 步骤 | 原来的实现 | 安卓上的问题 |
|---|---|---|
| 输入关键词 | `mp.input` 的文本输入框 | **没有键盘，打不了字、按不了回车** |
| 从列表选 | 装了 uosc → uosc 菜单<br>没装 uosc → `mp.input` 的 `选择:` 列表 | uosc 菜单靠鼠标区域，前端不转触摸就点不动<br>`选择:` 列表**纯键盘**（上下键 + 回车），完全不能用 |

实测日志里的典型现象：搜索**成功**返回了 2 条结果，然后卡死 ——
因为屏幕上是一个没人能操作的键盘列表。

本功能用三个开关把「打字」和「选择」这两步都跳过。

## 怎么开启无键盘支持

在 `script-opts/uosc_danmaku.conf` 里：

```ini
# 1. 一键搜索：拿文件名解析出的番剧名直接去搜，跳过打字
#    留空 = 不绑键（推荐，改用前端的自定义按钮发消息，见下一节）
danmaku_quick_search_key=

# 2. 自动选择：不弹列表，自动挑番剧 + 自动选集
#    本仓库默认就是 yes
danmaku_auto_select=yes

# 3. 流程跟踪：把每一步显示在屏幕上（只在排查时打开）
danmaku_verbose_osd=no
```

**安卓上最省事的组合就是「一键搜索 + 自动选择」**，全程不碰键盘：

```
按一下按钮
  → 从文件名解析出番剧名
  → 搜索
  → 自动挑一条最像的番剧
  → 按文件名推断的集数自动选集
  → 拉弹幕
```

## 一键搜索怎么触发

### 方式 A：前端自定义按钮（安卓推荐）

在 mpvex 等前端里加一个自定义按钮，动作填：

```
script-message danmaku-quick-search
```

这条消息也接受一个**可选参数**手动指定关键词，绕开文件名解析：

```
script-message danmaku-quick-search "孤独摇滚"
```

> 💡 关键词里可以带 `|` 分隔「名称|类型」，例如 `孤独摇滚 | tv`。
> 但**不建议写死**，因为动画条目通常在 `anime` 分类下，写 `tv` 可能反而过滤掉正确结果。
> 留空让它自己从文件名解析，换片子不用改配置。

### 方式 B：绑一个键（桌面 / 有键盘的设备）

```ini
danmaku_quick_search_key=Ctrl+j
```

留空（默认）就是完全不绑定。

### 关键词是怎么来的

从当前播放的文件名解析，例如：

| 文件名 | 解析出的搜索词 |
|---|---|
| `[DMG&VCB-Studio] BOCCHI THE ROCK! [01][Ma10p_1080p].mkv` | `BOCCHI THE ROCK` |
| `孤独摇滚 第01话.mkv` | `孤独摇滚` |

**网盘串流也能用** —— 播放 `network://…` 这类地址时，脚本会自动改用
`media-title` 里的真实文件名（`filename` 在那个场景下只是一串不透明的 ID）。

## 自动选择是怎么挑的

`danmaku_auto_select=yes` 之后，列表不再弹出，程序按规则自己挑。

### 第一步：先判断这是「剧集列表」还是「搜索列表」

判据不是猜标题，而是**看菜单项要执行的命令**（可靠）：

| 命令 | 含义 |
|---|---|
| `load-danmaku` | 某一集 → 这是剧集列表 |
| `search-episodes-event` / `get-extra-event` | 搜索到的番剧 → 这是搜索列表 |
| `open-latest-menu-anime` | 导航项（「↩️ 返回搜索结果」），**不参与选择** |

### 第二步：按列表类型挑

| 列表类型 | 挑选规则 |
|---|---|
| **剧集列表** | 按文件名推断出的集数**精确匹配**（`[01]` / `S01E04` / `第5话` 都认）。匹配不上取第一集；导航项永远跳过 |
| **搜索列表** | 按「标题相似度 + 类型关键词 + 噪音关键词」打分取最高 |

打分规则（固定表，可预期）：

```
分数 = jaro_winkler(文件名解析出的番剧名, 条目标题) × 100
     + 标题完全一致 ? 30 : 0
     + 类型关键词：动漫/番剧 +40，电影/剧场版 -35，真人 -30，电视剧 -20
     + 噪音关键词：countdown/特番/总集篇/预告/花絮/生放送… -20 ~ -40
     - min(标题比搜索词多出的字数, 40) × 0.8
```

> **为什么要惩罚「噪音关键词」和长标题**：特番、总集篇、预告这类条目
> 标题又长又像正片（比如 `S11 BOCCHI THE ROCK! Presents COUNTDOWN BOCCHI!`
> 前缀完全命中搜索词），但**往往根本没有弹幕**。不压下去就会挑中它，
> 结果弹一句「该集弹幕内容为空」。

### 连按保护

同一部番剧 / 同一集在 **5 秒内只会被处理一次**，连按按钮不会重复触发请求。
日志里会写：

```
[uosc_danmaku] 自动选择：忽略重复触发（搜索 / 孤独摇滚！）
```

> 这一步不是可有可无的：重复触发会排两次后续请求，而新请求一进来就会
> 取消上一个 —— 表现是 `HTTP 请求失败：Exit code: -2` 加一行 0 字节的
> curl 进度表（**真网络错误不会打出进度表**）。

### 挑错了怎么办

打分用的是几张固定的关键词表，**不可能穷尽**。挑错了就关掉它手动选：

```ini
danmaku_auto_select=no
```

## 无键盘选项全表（3 项）

| 选项 | 默认值 | 本仓库 | 说明 |
|---|---|---|---|
| `danmaku_quick_search_key` | `""`（不绑定） | `""` | 一键搜索的快捷键。留空则完全不绑键，改用 `script-message danmaku-quick-search` |
| `danmaku_auto_select` | `yes` | `yes` | 自动挑番剧 + 自动选集，不弹列表。⚠️ **0.8.6 起默认 `yes`**，此前是 `no` |
| `danmaku_verbose_osd` | `no` | `no` | 把 ①~⑧ 每一步**显示在屏幕上**。⚠️ 日志**不受**这个开关影响，见下 |

### 关于 `danmaku_verbose_osd`

从 **0.8.4** 起，流程日志（`[flow]` 开头）**永远会写进日志**，屏幕上看不见，
所以在安卓上排查问题**什么都不用配**就能拿到线索。这个开关只额外决定
「要不要同时显示在屏幕上」—— 平时会一直刷屏，排查完记得改回 `no`。


# 功能三：保存过滤后的弹幕

uosc_danmaku 本来就有 `save_danmaku`，但它存的是**原始**弹幕 ——
只跳过被屏蔽的源，不应用黑名单、不合并。也就是说你存下来的和你看到的
不是一回事，而且条数是最大的那一份。

本功能加了一个 `save_danmaku_mode`，让你选存哪一步之后的。

## 三种模式

| 模式 | 走哪套代码 | 实测条数（`[03]` 一集） | 带 `(12)` 标记 |
|---|---|---|---|
| `raw`（默认） | **上游原样实现** | 6592 | 否 |
| `filtered` | 新模块，去掉黑名单命中的 | 6579（屏蔽了「簽到」13 条） | 否 |
| `merged` | 新模块，再经 pakku 合并 | **4768** | **是** |

`merged` 存的是**快照**：文件里就是那条 `恭喜(12)`，重新加载观看体验和当时完全一致，
不用再合并一遍，条数也少得多（省 28%）。

> 想知道黑名单到底屏蔽了哪几条、或想拿一份「没合并过但已清理」的完整弹幕，
> 用 `filtered`。

## 存出来的文件会被再加工：阶段标签就是为这个加的

**问题**：`merged` 文件里的正文已经是 `恭喜(12)` 了。把它当普通弹幕源再跑一遍合并，
标记会被当成正文参与相似度：

```
原始 3 条「恭喜」  →  正常合并  →  恭喜(3)          ✓
再把 3 条「恭喜(12)」合并         →  恭喜(12)(3)     ✗ 计数叠加、文本被污染
```

实测拿真文件跑一遍：**4775 条会被错误地合成 4655 条**，冒出 `(12)(3)` 这种标记，
快照就毁了。

**做法**：保存时在文件里写一条**标准 XML 注释**记录「这份数据走到哪一步了」，
加载时读出来，已经做过的步骤不重做。

```xml
<?xml version="1.0" encoding="UTF-8"?><i>
<!-- uosc_danmaku:stage=merged -->
<d p="5,1,25,16777215">恭喜(12)</d>
...
```

- 用注释是因为它是**标准 XML** —— 其它播放器（DanDanPlay、网页播放器）会直接忽略，
  不会因为多了个属性报错
- `raw` **不写标签** —— 「没有标签」本来就等于 `raw`，所以不需要
- 标签是明文，你可以手改，也可以手写一个 `stage=filtered`

### 管线

```
弹幕文件 ──► 黑名单过滤 ──► pakku 合并 ──► 呈现（按合并数放大）
               │                │                  │
   raw ────────┘                │                  │
   filtered ────────────────────┘                  │
   merged ─────────────────────────────────────────┘
```

| 文件标签 | 过滤 | 合并 | 放大 |
|---|---|---|---|
| `raw` / 无标签 | ✅ | ✅ | ✅ |
| `filtered` | ✅（重做幂等，且尊重你当前的黑名单） | ✅ | ✅ |
| `merged` | ✅ | **❌ 跳过** | ✅ 从 `(12)` **反解出数量**再放大 |

`merged` 那一格是关键：xml 格式里塞不下「合并了几条」，所以单看文件是不知道
该放多大的。好在标记本身写着数量 —— 反解出来即可。实测 4775 条里有 791 条带标记，
其中 76 条会真的放大（最大 2 倍，对应合并 60 条）。

> `filtered` 在加载时**不需要特殊处理**：黑名单是个纯过滤，重做一遍结果一样，
> 而且这样你改了黑名单之后立刻生效。所以三个标签里只有 `merged` 会改变处理方式。

### 开关

```ini
save_danmaku_resume=auto     # 默认：按标签接着跑
```

改成 `ignore` 就忽略标签，一律当原始弹幕从头处理 ——
**改过黑名单或 pakku 参数之后，想拿旧快照重新跑一遍时用它**。

两种模式都会在日志里说明，不用猜：

```
[uosc_danmaku] 本地弹幕带阶段标签 merged：已完成的步骤不再重做
[uosc_danmaku] 本地弹幕已是合并后的快照：4775 条不再合并，其中 791 条还原了合并计数
[uosc_danmaku] 已解析 4775 条弹幕
```

> ⚠️ 一个边角情况：如果你在 `save_danmaku_mode=raw` 下**手动**执行
> `immediately_save_danmaku`，而那个路径正好是正在加载的快照文件，
> 会用无标签的版本覆盖它。自动保存不会（同名文件存在时上游会跳过）。

## 怎么用

```ini
save_danmaku=yes
save_danmaku_mode=merged
```

存到哪：默认视频同目录，文件名 `<视频名>.xml`（和 `autoload_local_danmaku`
认的名字一致，所以下次直接就能被加载）。想换个目录用 `save_danmaku_path`。

两种触发方式：

| 方式 | 时机 |
|---|---|
| 自动 | 播放结束 / 退出 mpv 时（需要 `save_danmaku=yes`） |
| 手动 | 随时执行 `script-message immediately_save_danmaku` |

> ⚠️ **`merged` 必须在弹幕已经显示过之后保存**，因为它用的是渲染时算好的结果。
> 如果那一刻还没有结果，会提示「还没有合并结果可保存，请先让弹幕显示一次」，
> 不会写出一个错的文件。
>
> ⚠️ 自动保存遇到**同名文件已存在**时会跳过（上游行为）。想覆盖就用手动触发。

保存成功会提示条数和模式：

```
[uosc_danmaku] 转换 XML 弹幕成功（merged，4768 条）：/path/to/xxx.xml
```

## 保存选项全表（2 项）

| 选项 | 默认值 | 本仓库 | 说明 |
|---|---|---|---|
| `save_danmaku_mode` | `raw` | `raw` | **存**哪一步之后：`raw` / `filtered` / `merged`。取值非法时回退 `raw` |
| `save_danmaku_resume` | `auto` | `auto` | **读**到带标签的文件时：`auto` 按标签接着跑 / `ignore` 忽略标签从头处理 |

`save_danmaku`、`save_danmaku_path`、`save_danmaku_path_mode`。

## 和上游代码是怎么共存的

这一段是给**要合并上游更新的人**看的。

`raw` 走的是**上游那段代码原样**（`parse.lua` 里 `convert_danmaku_to_xml()`
的原有实现，逐字节未改，已用 `git show` 对比验证过）。
`filtered` / `merged` 的实现放在**单独一个新文件** `modules/save_danmaku.lua`
—— 上游没有这个文件，所以永远不会冲突。

`parse.lua` 里对本功能只有三处极小改动，都带 `★` 标记，`grep '★'` 就能找全：

| 位置 | 改动 |
|---|---|
| 文件头 | 一行 `require("modules/save_danmaku")` |
| `is_blacklisted` 定义之后 | 一次 `set_deps{}`，把上游的局部件注入给新模块 |
| `parse_danmaku_file()` 末尾 | 额外返回一个「阶段标签」（老调用方只取第一个值，不受影响） |
| `convert_danmaku_to_ass_events()` 里 | 一行 `save_stage = …`（给条目挂上来源的阶段） |
| `convert_danmaku_to_ass_events()` 合并段 | 按阶段分流；**没有 `merged` 来源时 `pending` 就是原表，老路径一行没变** |
| `convert_danmaku_to_xml()` 开头 | 一个 3 行的转发；**下面是上游原样实现** |

`apis/dandanplay.lua` 里在 `add_danmaku_source_local()` 挂了一下阶段（2 行）。

所以合并上游时：上游改 `convert_danmaku_to_xml()` 的内部不会和本项目冲突
（它在 `↓↓↓ 以下为上游原样实现 ↓↓↓` 标记之下）；要改也只改新文件。

> **一个已知差异**：新模式的输出**按时间排序**，而 `raw` 沿用上游的
> 「不定序」（`pairs(DANMAKU.sources)` 的顺序不稳定）。
> 这是刻意的 —— `raw` 要保证和上游逐字节一致。想要排序好的完整弹幕，
> 用 `filtered`。

# 安装

## 方式一：整包覆盖（推荐）

把本仓库 `portable_config/` 里的内容覆盖到你的 mpv 配置目录：

```
<你的配置目录>/
├── scripts/uosc_danmaku/            ← 覆盖整个目录
└── script-opts/uosc_danmaku.conf    ← 覆盖此文件
```

配置目录通常是：

| 平台 | 路径 |
|---|---|
| Windows 便携版 | `portable_config/` |
| Windows 安装版 | `%APPDATA%/mpv/` |
| **安卓（mpvex）** | **`/storage/emulated/0/mpv/`** |

两者同时存在时 mpv 优先用 `portable_config/`。

> ⚠️ **请整个目录覆盖，不要只拷单个文件。** 只更新一部分文件会出现
> 「新日志格式 + 旧判定逻辑」混着跑的情况，从现象上完全看不出来。
> 排查时先看日志第一行的构建指纹（见[排查问题](#排查问题)）确认版本一致。

## 方式二：只给已有的 uosc_danmaku 打补丁

改动清单：

| 文件 | 改动 | 属于哪个功能 |
|---|---|---|
| `modules/pakku.lua` | **新增**，算法本体（约 1400 行） | 功能一 |
| `modules/save_danmaku.lua` | **新增**，保存模式的实现（上游没有这个文件，合并上游不冲突） | 功能三 |
| `modules/parse.lua` | 合并分支、标记加粗与字号处理；保存模式**只加了一个转发**，上游实现原样保留 | 功能一 + 三 |
| `modules/options.lua` | 23 个 `pakku_*` + 3 个 `danmaku_*` + 1 个 `save_danmaku_*` 选项默认值 | 全部 |
| `main.lua` | `require("modules/pakku")`、一键搜索键绑定、构建指纹 | 功能一 + 二 |
| `modules/utils.lua` | `trace_osd` / `http_error_hint` / `get_media_filename` 等 | 主要功能二 |

因为核心是「**1 个新增模块 + 若干处条件分支**」，回滚不影响 uosc_danmaku 的其它功能。

# 常见问题

**Q：打开后弹幕数量没变？**
确认改的是 mpv 实际读取的那个 `uosc_danmaku.conf`（`portable_config/` 优先于
`%APPDATA%/mpv/`）。用 `--msg-level=uosc_danmaku=v` 看有没有
`pakku: 拼音字典载入` 这行。

**Q：合并得太狠了，不相干的弹幕被合到一起。**
调小 `pakku_max_dist`（3 或 2），调大 `pakku_max_cosine`（70），
或关掉 `pakku_cross_mode` 避免跨类型吸走弹幕。

**Q：合并得不够，还是刷屏。**
调大 `pakku_max_dist`（6）、调小 `pakku_max_cosine`（35）、
调大 `pakku_threshold`（60）。

**Q：某些弹幕的字变了。**
那是文本预处理在起作用（去尾部标点、全角转半角）。
想显示原文就设 `pakku_normalize_display=no`。

**Q：弹幕变得很大 / 很小。**
大是 `pakku_enlarge`（默认合并 25 条就翻倍），小是 `pakku_shrink_threshold`。
分别关掉即可。

**Q：`HTTP 请求失败：Calling failed. Exit code: -2`，还带着一行 `0 0 0 0`？**
那不是网络问题，是**请求被自己掐掉了**：连按了两下按钮，两次搜索各自排了一次
后续请求，而新的请求一进来就会取消上一个，把正在跑的 curl 杀掉。
`-2` 是进程被终止，那行 `0 0 0 0` 是 curl 的进度表 —— **真网络错误不会打出进度表**。
5 秒内的重复选择现在会被自动忽略，正常点不会出现。

**Q：自动选择挑中的番剧「该集弹幕内容为空」？**
多半选中了特番/总集篇/预告。这类条目标题又长又像正片，而且经常没有弹幕。
打分里已经对 `特番`/`总集篇`/`预告`/`countdown` 之类扣了分，但关键词表不可能
穷尽 —— 遇到了把 `danmaku_auto_select` 改回 `no` 手动选一次。

**Q：搜索能用，但列表弹出来选不了（`选择:` 那个框）。**
说明没装 uosc，走的是 `mp.input` 的**纯键盘**列表。开 `danmaku_auto_select=yes`。

**Q：保存弹幕时提示「还没有合并结果可保存」。**
`save_danmaku_mode=merged` 用的是渲染时算好的结果，得等弹幕**显示过之后**再存。
如果你在弹幕加载出来之前就触发了保存，等几秒再试；一直这样说明弹幕压根没加载成功
（先按[排查问题](#排查问题)看 `已解析` 有没有出现）。

**Q：`save_danmaku=yes` 了，但退出时没存。**
自动保存遇到**同名文件已存在**会跳过（上游行为）。想覆盖就手动触发一次：

```
script-message immediately_save_danmaku
```

**Q：存出来的 `.xml` 里为什么有 `(12)` 这样的字？**
那是 `save_danmaku_mode=merged` 的合并标记，和屏幕上显示的一致 —— 这是**故意**的，
重新加载观看体验才和当时一样。不想要就用 `filtered` 模式。

**Q：支持哪些弹幕类型？**
滚动（1/2/3）、底部（4）、顶部（5）参与合并。逆向（6）、高级（7）、
代码（8/9）弹幕原样透传不做合并。

**Q：和 uosc_danmaku 自带的 `merge_tolerance` 冲突吗？**
互斥。`pakku_enable=no` 时用 `merge_tolerance`（行为完全不变）；
`pakku_enable=yes` 时 `merge_tolerance` 被忽略。
`merge_fontsize_growth` / `merge_fontsize_max` 同样在 pakku 模式下不生效。
`max_screen_danmaku`（同屏条数限制）两者都生效，在合并之后执行。

**Q：会不会拖慢播放？**
不会。合并在弹幕加载时一次性完成，一集约 320ms，播放过程中零开销。

# 排查问题

## 0. 先看构建指纹

从 **0.8.7** 起，脚本启动时会打印一行：

```
[uosc_danmaku] uosc_danmaku+pakku 2.2.0 build 6/209549/47053486
```

它对 6 个关键文件（`main.lua` / `menu.lua` / `utils.lua` / `options.lua` /
`parse.lua` / `dandanplay.lua`）做内容指纹。

> **换了新脚本后这行没变，就是文件没拷全。** 之前吃过一次亏：只更新了
> `utils.lua` 没更新 `menu.lua`，新旧混着跑，从现象上完全看不出来。

## 1. 确认脚本加载了

```powershell
mpv.exe --msg-level=all=v "视频.mkv" 2>&1 | Select-String "uosc_danmaku"
```

应能看到 `Loading lua script .../uosc_danmaku/main.lua`。

## 2. 确认 pakku 生效了

在同一输出里找 `pakku: 拼音字典载入 6763 个汉字 / 398 个拼音组`。
没有这行说明没被调用 —— 检查 `pakku_enable=yes` 是否写对、
conf 文件编码是不是 UTF-8。

## 3. 确认本地弹幕被加载了

- 视频时长 **≥ 60 秒**
- 弹幕文件叫 `<视频文件名不含扩展名>.xml`，放在视频同目录
- `danmaku-history.json` 里的 `show_danmaku` 是 `true`

## 4. 弹幕搜索卡住 / 没反应

**什么都不用配，直接看日志里的 `[flow]` 行**（0.8.4 起永远输出）：

```
[flow] ① 关键词：孤独摇滚
[flow] ② 搜索「孤独摇滚」，1 个服务器
[flow] ③ https://... 失败：exit 7 连不上服务器：Failed to connect
[flow] ④ 合计 0 条搜索结果
```

停在哪一号，问题就在那一步。**⑤ 尤其重要**，它说明屏幕上是哪种选择界面：

| ⑤ 的输出 | 含义 |
|---|---|
| `显示 uosc 菜单` | 装了 uosc、前端也能把触摸转成鼠标，就没事 |
| `显示键盘列表` | 弹的是 `mp.input` 的 `选择:` 列表，**安卓上根本选不了** → 开 `danmaku_auto_select=yes` |
| `无可用的选择界面` | 既没 uosc 也没 `mp.input`。这条以前是完全静默的 |

另外两条排错用的说明：

```
[flow] 列表判定[搜索]：搜索列表 → 按标题打分（2 条，文件名集数 1）
[flow] 打分参考词「BOCCHI THE ROCK」，前三：孤独摇滚！=48.3 / 孤独摇滚！ 剧场总集篇=-19.7
```

- `列表判定` 说明这份列表被当成了什么、是谁在选（`[搜索]` / `[剧集]` / `[列表]`）
- `打分参考词` + `前三` 说明为什么是它分最高

## 5. 各种「失败」提示

| 提示 | 含义 |
|---|---|
| `弹幕获取失败：exit N …` | 请求 `api_server/api/v2/comment/<剧集id>` 失败 |
| `剧集数据获取失败：exit N …` | 请求 `api_server/api/v2/bangumi/<id>` 失败（拉剧集列表） |
| `该集弹幕内容为空（服务器 / 剧集 N）` | 请求成功了，但那一集确实没弹幕 |

`exit N` 是 curl 的退出码，脚本已翻译成人话：

| 提示 | 通常意味着 |
|---|---|
| `exit -3 子进程没起来（可能缺 curl）` | mpv 调不起 `curl`。安卓上常见 —— **mpv-android 不自带 curl** |
| `exit -2`（同一行还有 `0 0 0 0` 进度表） | **不是网络错误**，是请求被取消/进程被终止。见上面那条常见问题 |
| `exit 6 域名解析失败` | `api_server` 域名解析不了 |
| `exit 7 连不上服务器` | 端口不通，可能被运营商/防火墙拦了 |
| `exit 22 HTTP 返回错误状态码` | 服务器返回 4xx/5xx |
| `exit 28 请求超时` | 服务器太慢或被墙 |
| `exit 35` / `60` | TLS 握手失败 / 证书不受信任（系统时间不对也常见） |
| `exit 51` / `52` / `56` | 证书校验失败 / 服务器无响应 / 接收数据失败 |

能做什么：

- `api_server` 支持**多个地址**（英文逗号分隔），会并发试，可以多填几个
- 换 `danmaku_auto_select=no` 手动选一次，能区分是选择问题还是网络问题

## 6. 怀疑是 pakku 引起的异常

把 `pakku_enable` 改成 `no` 对比。两者差异只应该在「合并了什么」上。

## 7. 怎么把日志抓出来（安卓）

导入 mpvex 等前端的「导出日志」即可 —— **`[flow]` 行是 info 级，会包含在里面**，
不用改任何配置。

如果想看 `verbose` 级（`[flow]` 覆盖不到的地方），在 `mpv.conf` 里加：

```ini
log-file=/storage/emulated/0/mpv/mpv.log
msg-level=all=info,uosc_danmaku=v
```

⚠️ 日志文件涨得很快，排查完记得删掉这两行。

**发日志给别人排查前请删掉隐私**：`uosc_danmaku.conf` 里的 `api_server`、
`tmdb_api_key`，以及日志里出现的文件路径 / 网盘账号信息。

## 8. 跑单测（改代码时）

```bash
luajit test/auto_select_test.lua     # 通过 47，失败 0
luajit test/save_danmaku_test.lua    # 通过 66，失败 0
luajit test/docs_check.lua           # 通过 8，失败 0
```

- `auto_select_test.lua` 覆盖自动选择的全部判定逻辑（列表类型识别、集数匹配、
  导航项跳过、跨入口去重、收尾只跑一次）
- `save_danmaku_test.lua` 覆盖三种模式各自取哪些条目、（`raw` 时必须**让回给上游**）、
  `merged` 用快照且保留标记、按时间排序、XML 转义、非法取值回退、没注入依赖时的报错，
  以及**阶段标签的读写、`(N)` 反解、`split_by_stage` 分流**
- `docs_check.lua` **核对文档和代码是否还对得上**：`options.lua` 里每个选项是不是
  都在 readme 里写了、readme 里写的默认值和代码是否一致、文档引用的函数名是否
  真实存在、目录锚点和表格是否有效

前两个测试都**直接从 `menu.lua` / `parse.lua` 里切真实代码来跑**，
所以实现改了测试没跟上会立刻失败。**加选项或改默认值之后请跑一下
`docs_check.lua`** —— 它专门盯「代码改了文档忘了改」。

## 9. 保存出来的弹幕不对

先看日志里的这一行，它会写明**模式和条数**：

```
[uosc_danmaku] 转换 XML 弹幕成功（merged，4775 条）：/path/to/xxx.xml
```

对照下面判断：

| 现象 | 原因 |
|---|---|
| 条数和弹幕总数一样，没有 `(12)` | 模式还是 `raw`（默认值），改成 `merged` |
| 条数没变，但黑名单没生效 | `blacklist_path` 没配对，或模式是 `raw`（raw 不过滤黑名单） |
| 提示「还没有合并结果可保存」 | `merged` 需要在弹幕显示过之后保存 |
| 提示「已存在同名弹幕文件」 | 自动保存不覆盖已有文件，手动触发 `immediately_save_danmaku` |
| 提示「此弹幕文件不支持保存至本地」 | 播的是网络串流且没设 `save_danmaku_path` |

# 性能

3 集真实弹幕（合计 20086 条）实测，mpv v0.41.0 / LuaJIT，`fontsize=50`：

| 配置 | 合并结果 | 平均耗时 |
|---|---|---|
| 关闭 | 20086 → 20086 | 0 ms |
| **默认** | **20086 → 14366（71.5%）** | **~319 ms/集** |
| `threshold=10` | 20086 → 15340（76.4%） | ~181 ms/集 |
| `threshold=5` | 20086 → 16216（80.7%） | ~141 ms/集 |
| 保守（`dist=3` `cos=70`） | 20086 → 15385（76.6%） | ~292 ms/集 |
| 不跨类型（`cross=no`） | 20086 → 15273（76.0%） | ~256 ms/集 |
| 仅精确 + 拼音（`dist=0`） | 20086 → 17665（87.9%） | ~135 ms/集 |

单集明细：

| 集数 | 原始 | 合并后 | 最大合并 | 耗时 |
|---|---|---|---|---|
| 03 | 6592 | 4773 | (60) | ~306 ms |
| 04 | 6702 | 4884 | (69) | ~314 ms |
| 07 | 6792 | 4709 | (47) | ~307 ms |

耗时都在**弹幕加载时**（一次性），播放过程中没有额外开销。
拼音字典首次使用时懒加载约 60ms，之后常驻内存。
同一输入重复运行结果完全一致（合并过程是确定性的）。

# 关闭与卸载

## 只关功能一（pakku 合并）

```ini
pakku_enable=no
```

立刻回到上游行为（`merge_tolerance` 重新生效）。

## 只关功能二（无键盘支持）

```ini
danmaku_auto_select=no
```

回到「弹列表让你选」，桌面装了 uosc 的话可以正常用。

## 只关功能三（保存过滤后的弹幕）

```ini
save_danmaku_mode=raw
```

回到上游原有的保存行为（存原始弹幕）。想连保存本身也关掉就
`save_danmaku=no`。

## 完全卸载

删掉 `scripts/uosc_danmaku/modules/pakku.lua`，并把其余文件里的相关代码去掉
（见[安装 → 方式二](#方式二只给已有的-uosc_danmaku-打补丁)的改动清单）。

因为是「1 个新增模块 + 若干处条件分支」，回滚不会影响 uosc_danmaku 的其它功能。
